# قائمة الصيانة والحوادث — بوابة الخير (الإصدار 1.0.0-rc.1)

الأوامر الكاملة في `DEPLOYMENT_AR.md`، وحالات الفقد في `BACKUP_RECOVERY_AR.md`. لا تكتب هنا أي سر.
كل الأوامر تُنفّذ من مجلد `deploy` على الخادم.

## 1. صيانة دورية

### يوميًا
- [ ] قناة التنبيه: لا رسائل «PROBLEM» غير معالجة؛ وخدمة `monitor` تعمل (`docker compose ps`).
- [ ] `ops:status`: الحالة 0. إن كانت 3 أو 1 فاقرأ أي بند ليس `ok`.
- [ ] `local_backup` عمره أقل من 24 ساعة (أو حسب الجدول المعتمد في DR-2).
- [ ] `offsite_copy` متحقَّق منه (بعد إعداد التخزين الخارجي).
- [ ] لا ارتفاع غير عادي في `login_failures_last_hour`.

### أسبوعيًا
- [ ] `docker compose --env-file .env run --rm cli db:check` → `"ok": true`.
- [ ] تاريخ انتهاء الشهادة (من جهاز له إنترنت):
  ```sh
  echo | openssl s_client -connect <النطاق>:443 -servername <النطاق> 2>/dev/null | openssl x509 -noout -enddate
  ```
- [ ] المساحة الحرة (`disk_data` و`disk_backups`) أكبر من ضعف حجم القاعدة.

### شهريًا
- [ ] **فحص الصور أمنيًا:**
  - صورة التطبيق وصورة Caddy المثبتة بالـ digest، بـ Trivy أو ما يعادله، مع تسجيل تاريخ قاعدة الثغرات.
  - لصورة Caddy أيضًا: `govulncheck -mode=binary` على `/usr/bin/caddy`.
  - قارن بالقرار DR-6.
- [ ] **إصدار Caddy أحدث رسميًا** (مبني بـ Go ≥ 1.27.4، وx/net ≥ 0.62، وgo-jose مُصلَح)؟
  - حدّث الـ digest في `compose.yaml`؛
  - ثم أعد فحوص الـ proxy (HTTP→HTTPS 308، Host≠SNI 421، جسم ≥ 3MB معلن 413، الكوكيز) ورحلة متصفح واحدة على الأقل.
- [ ] **إصدار Node 24 أمني جديد؟** حدّث الـ digest في `Dockerfile`، وأعد البناء والفحص والاختبارات.
- [ ] **تمرين استعادة كامل:**
  - على مشروع أو خادم منفصل؛
  - من نسخة **منزّلة من التخزين الخارجي**؛
  - سجّل الزمن ونتيجة `db:check`.
- [ ] **مراجعة الحسابات الإدارية وسجل التدقيق:** هل كل مدير ما زال يحتاج حسابه؟
- [ ] **التحقق من نسختي الأسرار** خارج الخادم: موجودتان ويمكن الوصول إليهما.

### ممنوعات دائمة
- **لا تُفعّل في Caddyfile دون مراجعة أمنية جديدة:**
  - `request_body`؛
  - `acme_server`؛
  - واجهة الإدارة (`admin`)؛
  - `encode zstd`؛
  - أي وحدة تعالج HTML.

  السبب: الثغرات المتبقية في صورة Caddy 2.11.9، في `FINAL_ACCEPTANCE_18.md` §3.
- **عدد النسخ:**
  - لا تزد نسخ التطبيق عن واحدة؛
  - لا تضع البيانات على NFS/SMB؛
  - لا تحذف أي volume.
- **لا تحديث أو ترحيل تلقائي.** الترحيل بالأمر `db:migrate --confirm-backup` بعد نسخة متحقَّق منها.

## 2. التحديث (ملخص)
1. ابنِ الصورة الجديدة وافحصها.
2. شغّل `backup:run` يدويًا وتأكد من نجاحه.
3. أوقف `backup` ثم `app`.
4. غيّر `ALKHAYR_VERSION`، ثم `db:migrate --confirm-backup` إن وُجدت ترحيلات.
5. شغّل `up -d app backup`، ثم `db:check`.
6. تحقّق: `/readyz`، ودخول مدير، ودخول تاجر.

**الرجوع:**
- **بلا ترحيل:** أعد الإصدار السابق (قيس محليًا: 0.8 ث).
- **بعد ترحيل:** الإصدار القديم يرفض القاعدة (`SCHEMA_TOO_NEW`). الرجوع = استعادة نسخة ما قبل الترحيل على مشروع منفصل،
  مع **فقد كل ما كُتب بعدها**. هذا قرار إداري، لا خطوة تلقائية.

## 3. الحوادث — ماذا تفعل أولًا

| الحادثة | أول خطوة | لا تفعل |
|---|---|---|
| وصلت رسالة تنبيه (PROBLEM / CHANGED) | شغّل `ops:status` واقرأ البنود غير `ok`، ثم اتبع الصف المناسب أدناه | لا تُعِد تشغيل الحاويات لإسكات التنبيه |
| الموقع لا يفتح | `docker compose ps`، و`logs --tail 200 proxy app` | لا تحذف volumes ولا تشغّل `db:init` |
| `/readyz` يظهر `writes: closed` دون استعادة | `db:check` واحفظ الناتج؛ أبلغ صاحب العمل | لا تعدّل القاعدة يدويًا |
| فشل النسخ (`backup_job` حرِج) | اقرأ `lastErrorCode` في `ops:status`؛ `DISK_FULL` ← حرّر مساحة بـ `backup:prune --keep N` بعد التأكد من نسخة خارجية | لا تحذف آخر نسخة متحقَّق منها |
| تعذّر التخزين الخارجي | تحقّق من الشبكة وبيانات الاعتماد، ثم `backup:run` يدويًا | لا تضع المفاتيح في `.env` |
| فشل الشهادة | DNS، والمنفذان 80/443، و`logs proxy`، وحدود Let's Encrypt | لا تعطّل HTTPS ولا تغيّر `APP_ORIGIN` إلى http |
| ارتفاع محاولات الدخول الفاشلة / 503 عند الدخول | سجّل المصادر من سجلات الـ proxy؛ تواصل مع التاجر المستهدف؛ القرار DR-3 | لا تعطّل حدود المحاولات |
| اشتباه اختراق حساب مدير | أوقف `app`، ثم `account:revoke-sessions`، و`account:reset-password`، و`account:reset-mfa`، ثم شغّل `app` وراجع سجل التدقيق | لا تشارك الرموز الجديدة عبر الدردشة |
| فقد الخادم أو القرص | خادم جديد ← الأسرار من الحفظ الخارجي ← `backup:offsite-get` ← `backup:verify` ← `backup:restore` ← المصالحة ← `recovery:reopen` | لا تفتح الكتابة قبل المصالحة |
| تسريب `backup.key` | أنشئ مفتاحًا جديدًا (`backup:keygen`) ونسخة جديدة فورًا؛ اعتبر النسخ القديمة مكشوفة لمن يملك الملفات | لا تحذف النسخ القديمة قبل التأكد من الجديدة |
| ثغرة أمنية معلنة في Node أو Caddy | قيّم الوصول في إعدادنا، ثم حدّث وفق القسم 2 | لا تبنِ Caddy مخصصًا دون مراجعة (DR-6) |

بعد كل حادثة: سجّل الوقت، والسبب، وما فُقد، وما صُحِّح، ومن قرّر.
