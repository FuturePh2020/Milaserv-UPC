# ALKHAYR — Security Policy (contract)

Status: **Policy defined in stage 00. No control is implemented or tested yet.** Each control's
"Verified" state is tracked in PROJECT_STATE.md and later TEST_REPORT.md. Historical results from
the earlier 2.0.1 project (22 tests / zero advisories) do **not** apply to this codebase.

## 1. Prohibited in every build
- Guest ordering, default admin, first-user-is-admin, hardcoded/test logins, review-mode/preview bypass.
- Trusting identity/role headers (e.g. ChatGPT/OpenAI user headers, `X-User-Role`, `X-Merchant-Id`).
- Auth tokens in localStorage/sessionStorage; tokens in URLs.
- Wildcard CORS with credentials (no CORS at all: same-origin SPA).
- HTTP endpoints for backup download, restore, admin creation, password or MFA reset.
- Generated fallback secrets. Placeholder secrets in production → startup failure.
- Mock/fake success responses standing in for real backend behaviour.

## 2. Passwords
- scrypt (Node `crypto`), N=131072, r=8, p=1, 16-byte random salt, 32-byte key,
  `maxmem = 256 MiB`. Measured here: ≈ 340 ms per hash on the dev container (stage-00 probe).
- Bounded concurrency: at most 2 concurrent hashes (configurable), queue ≤ 32; overflow → 429/503.
- Constant-time comparison (`timingSafeEqual`). Unknown usernames verify against a dummy hash so
  timing does not reveal existence.
- Length: traders ≥ 12, admins ≥ 15, max 128 characters **and** 512 UTF-8 bytes. Unicode NFC normalized.
  No composition rules. (Optional breached-list check: out of scope; no external call.)

## 3. Administrator MFA (TOTP, RFC 6238)
- 20-byte random secret, SHA-1, 6 digits, 30 s step, window ±1.
- Anti-replay: `UPDATE auth_users SET last_otp_step=? WHERE id=? AND (last_otp_step IS NULL OR last_otp_step < ?)` — affected rows must be 1.
- Secret encrypted with AES-256-GCM; key = HKDF-SHA256(APP_SECRET, info="alkhayr:totp:v1"); 12-byte
  random nonce; AAD = user id. Shown once by CLI `setup-admin`/`reset-mfa`; no route returns it.

## 4. Keys
| Key | Source | Use |
|---|---|---|
| `APP_SECRET` | ≥ 32 random bytes (base64url), generated by operator locally | HKDF to purpose keys: totp, csrf, cursor, ip-hmac, rate-limit |
| `BACKUP_KEY` | independent 32 random bytes | AES-256-GCM backup encryption; stored off-host separately |
Validation at startup: present, decodes to ≥ 32 bytes, not a documented placeholder, `BACKUP_KEY ≠ APP_SECRET`.
SQLite itself is **not** encrypted at rest; disk encryption is a hosting responsibility.

## 5. Sessions & cookies
- Token: 32 random bytes (base64url); DB stores SHA-256 only.
- Cookie (production): `__Host-alkhayr_session`; `Secure; HttpOnly; SameSite=Strict; Path=/`; no Domain.
  Development over plain http://localhost uses `alkhayr_session` without Secure (dev only, D-007).
- Idle: admin 15 min, trader 30 min. Absolute: 8 h. Max 5 per user (oldest evicted).
- Rotation on login; all sessions revoked on password change/reset, suspension, MFA reset, restore.
- Admin mutations require `auth_at` within 15 min → else `428 RECENT_AUTH_REQUIRED`.
- Session validity also requires `sessions.password_changed_at == auth_users.password_changed_at`
  and merchant not suspended (checked on every request).

## 6. CSRF & origin
- Session-bound token: HMAC(csrfKey, session.csrf_secret). Pre-login: signed challenge (10 min) bound
  to a pre-session cookie, required for login/register.
- Every mutation: exact `Origin` match with `APP_ORIGIN` (missing Origin → reject), CSRF header,
  `application/json` content type. `Host` must equal the configured host.

## 7. Request hardening
- Body limit enforced while streaming (default 64 KiB, import 2 MiB) → 413.
- Collection length checks before detailed validation (items ≤ 100, import rows ≤ 1000).
- Server timeouts: `headersTimeout` 15 s, `requestTimeout` 30 s, keep-alive 5 s; max header 16 KiB.
- Rate limits (durable, SQLite): login 5/15 min per account + 20/15 min per IP; register 5/h per IP;
  general API 300/min per session; CSV import 10/h per admin. Values configurable; trade-off: a
  determined attacker can lock a username's login temporarily (documented availability trade-off).
- `TRUST_PROXY` lists exact proxy IPs; X-Forwarded-For used only when the socket peer is one of them.

## 8. Headers
`Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' https: data:; font-src 'self'; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'; object-src 'none'`
(any `style-src 'unsafe-inline'` exception must be justified in DECISIONS.md),
`X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`,
`Cross-Origin-Opener-Policy: same-origin`, `Permissions-Policy` minimal, HSTS (via proxy in production),
`Cache-Control: no-store` on API responses. No remote fonts/CDNs in production (fonts self-hosted).

## 9. Data access
- Parameterized SQL only; sort/filter via allow-lists; no string-built SQL from input.
- Ownership enforced in the query (`WHERE merchant_id = :sessionMerchant`), not only after fetch.
- Not-owned resources return 404.

## 10. Logging & audit
- No passwords, tokens, cookies, CSRF values, TOTP codes, secrets or login bodies in logs.
- IP stored only as HMAC(ipKey, ip); retention 365 days for audit, 30 days for rate-limit rows.
- Audit metadata uses allow-listed keys per action.

## 11. Supply chain
- Pinned versions in `package-lock.json`; minimal dependency set; `npm audit` run and dated in
  stage 16 (discloses dependency metadata to the registry — noted). SBOM + license notices in release.
- No claim of "zero vulnerabilities" without a dated scan; scans do not cover OS images unless run.
