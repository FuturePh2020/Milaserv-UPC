# ALKHAYR — Database Contract

Status: **Specified in stage 00; not yet implemented.** Stage 02 turns this into
`migrations/0001_initial.sql` and tests it. Any deviation must be recorded here and in DECISIONS.md.

## 1. Engine and connection policy
- SQLite ≥ 3.45 via Node's built-in `node:sqlite` on Node 24 (D-004; fallback `better-sqlite3`).
- One application process owns the file. Local persistent disk only — **no NFS, no multiple app
  instances on the same file**.
- PRAGMAs on every connection: `journal_mode=WAL`, `foreign_keys=ON`, `busy_timeout=5000`,
  `synchronous=FULL` (durability over throughput for a financial pilot), `trusted_schema=OFF`.
- Writes that must serialize use `BEGIN IMMEDIATE`. A transaction body is **synchronous only**:
  no `await`, network, password hashing or timers inside it.
- Integers for money (piasters) and quantities (cartons). Timestamps: INTEGER Unix epoch
  **milliseconds** UTC. IDs: TEXT UUID v4 (lowercase, generated by `crypto.randomUUID()`).
- Booleans: INTEGER 0/1 with CHECK.

## 2. Tables

### auth_users
| column | type | rules |
|---|---|---|
| id | TEXT PK | UUID |
| username | TEXT NOT NULL | stored normalized (NFKC, lowercase); `UNIQUE` + `COLLATE NOCASE`; CHECK length 3–32 |
| password_hash | TEXT NOT NULL | `scrypt$N$r$p$saltB64$hashB64` |
| password_changed_at | INTEGER NOT NULL | used to invalidate sessions on reset |
| role | TEXT NOT NULL | CHECK IN ('admin','trader') |
| totp_ciphertext | TEXT NULL | AES-256-GCM envelope; required when role='admin' (enforced by service + CHECK) |
| last_otp_step | INTEGER NULL | anti-replay; updated atomically `WHERE last_otp_step IS NULL OR last_otp_step < ?` |
| created_at | INTEGER NOT NULL | |
| updated_at | INTEGER NOT NULL | |

### order_events (append-only)
`id INTEGER PK AUTOINCREMENT, order_id FK, actor_user_id FK NULL, old_state NULL, new_state, note NULL, created_at`.
Index `(order_id, id)`. Triggers `BEFORE UPDATE/DELETE → RAISE(ABORT)`.

### inventory_ledger (append-only)
| column | type | rules |
|---|---|---|
| id | INTEGER PK AUTOINCREMENT | |
| product_id | TEXT NOT NULL | FK |
| actor_user_id | TEXT NULL | FK |
| kind | TEXT NOT NULL | CHECK IN ('opening','receipt','correction','reserve','release','ship','import') |
| on_hand_delta, reserved_delta | INTEGER NOT NULL | not both 0 |

### audit_logs (append-only)
`id INTEGER PK, actor_user_id NULL ('anonymous' when NULL), action TEXT (controlled code),
target_type TEXT NULL, target_id TEXT NULL, metadata TEXT NULL (JSON, allow-listed keys only, ≤ 2 KiB),
ip_hmac TEXT NULL, request_id TEXT NOT NULL, created_at`.
Index `(created_at, id)`, `(actor_user_id, created_at)`. Retention: 365 days (D-014), purge via CLI.

### rate_limits
`key TEXT PK (HMAC of bucket+IP/account), count INTEGER, window_ends_at INTEGER`.
Expired rows purged opportunistically (bounded batch of 500) and on a timer.

### business_settings (single row, id = 1)
`id INTEGER PK CHECK(id=1), company_name, company_phone, company_email NULL, company_address,
shipping_cents INTEGER CHECK 0…10000000, tax_bps INTEGER CHECK 0…10000,
minimum_order_cents INTEGER CHECK 0…1000000000, version INTEGER, updated_at, updated_by NULL`.
Created by migration with neutral placeholders that the operator must set (no statutory tax assumed;
default `tax_bps=0`, `shipping_cents=0`, `minimum_order_cents=0`).

### schema_migrations
`version INTEGER PK, name TEXT, checksum TEXT (SHA-256 of file), applied_at INTEGER`.

## 3. Migration policy
1. Migrations are numbered SQL files `migrations/NNNN_name.sql`, applied in order, each in its own
   transaction, recorded with checksum.
2. On startup: if any applied checksum differs from the file → **refuse to start**. If the DB
   records a version newer than the code knows → **refuse to start** (newer-schema guard).
3. Applied migrations are never edited; fixes are new migrations.
4. Migrations run at startup/CLI only, never inside an HTTP request.
5. No production seed admin; no demo seed unless `ALLOW_DEMO_SEED=true` in non-production.
6. Destructive change (drop/rename with data) requires: verified encrypted backup, test on a copy,
   before/after counts and financial totals comparison, documented in MIGRATION.md.
7. Repeated startup must not reseed or reset data.
